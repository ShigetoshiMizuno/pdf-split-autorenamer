## Blockers, Gotchas & Workarounds

### NEW（本セッション発見）

- **WeasyPrint は Windows で GTK Runtime 必須** → `winget install tschoonj.GTKForWindows` でインストール。`os.add_dll_directory` だけでは pytest+cffi が PATH を参照するため不足、`conftest.py` で `os.environ['PATH']` 追加も必要
- **`extract_vendor` の `\s*` が改行をまたいでマッチ** → `[^\S\n]*` に変更必須。さらに `_DATE_IN_VENDOR` フィルタで戻り値の日付混入を防衛
- **担当者名の境界識別困難** → `_DEPT_ROLE_PATTERN` で部署/役職前を切り詰め。ただし「ABC開発部株式会社」のような社名本体に部署名を含むケースは「raw 末尾で空白なし」なら保持するロジックで対応
- **`pytest.importorskip("weasyprint")` は `conftest.py` より前に動く** → conftest.py で先に DLL を PATH に通しても、importorskip 時点で cffi が PATH を再評価しないと load 失敗する。`os.environ['PATH']` 追加が必須
- **`gh pr edit` での日本語 body** → HEREDOC で `<<'EOF'` 形式（変数展開無効化）が必須、PowerShell ではなく Bash 経由で実行する

### 既知（午前から継続）
- PyMuPDF `insert_text(rotate=...)` は整数 0/90/180/270 のみ受け付ける
- Windows ターミナルが cp932 で日本語パス・出力を文字化け表示（動作影響なし、検証時は `with open(..., encoding="utf-8")` でファイル保存し Read で確認）
- `docs/demo/sample_office_scan.pdf` は git 管理下（`.gitignore` で `!docs/demo/*.pdf` 例外）

## Key Learnings & Gotchas (長期記憶へ移行推奨)

- **WeasyPrint は Windows でも純 Python レンダラーだが GTK Runtime（pango/cairo/glib）は別途必要**。winget 推奨パッケージ: `tschoonj.GTKForWindows`（v3.24.31）
- **PyMuPDF + TTFont(subfontIndex=0) は表示 OK でもテキスト抽出 NG**（CID→Unicode CMap が不完全）。日本語 PDF を生成して `get_text()` で取り直したい用途には WeasyPrint が確実
- **TDD コミット戦略**: テスト追加 `[RED]` → 実装 `[GREEN]` → docs/chore の 3 段階で分けると QA レビュー時の差分把握が劇的に楽になる
- **「書類タイプ」概念は粒度が荒い**: 業務 PDF 整理では「カテゴリ + 取引先 + 文書番号」のサマリー化が本質的に必要
- **PRG ちゃん委譲時の指示の粒度**: 「期待値・フォーマット・ファイルパス・行番号・置換マップ」を具体例付きで渡すと一発で動く。曖昧な指示だと境界条件で詰まる
- **QA → 改良 → QA の反復は 3-4 ラウンドで「製品 OK」に達する**。各ラウンドで Blocker 0 + 重大改善推奨 0 を目指せばよい。Round 3 で W-A のような edge case が見つかるのは健全な兆候
- **`extract_vendor` の部署名問題**: 法人名と担当者名の境界は本質的に難しい。「raw 末尾で空白なし」を「社名の一部」と扱うヒューリスティクスは実用上有効
